# 阶段六：独立桌宠文本对话（0.6.0 Preview）

本阶段完成工坊对话设置、文本发送与最近四轮上下文、取消/清空/超时、错误提示、桌宠回复气泡和思考/挥手动作。首次输入模型 ID 与 API Key 并保存，点击发送才会调用 `https://api.openai.com/v1/responses`。费用由配置的 API 账户承担；没有默认模型、内置密钥或自动后台请求。

密钥通过 Electron safeStorage 异步接口加密后写入用户数据目录，系统加密不可用时拒绝保存新密钥。留空保留原密钥，移除密钥按钮删除已保存的密文。配置通过临时文件重命名替换，失败保留旧配置。密钥不会通过读取配置接口返回渲染器，也不进入诊断报告、Git 或发布包。密文依赖当前系统账户，不保证跨电脑可解密；迁移后需重新配置。

对话上下文只在主进程内存保留最多四轮成功对话。0.6.0–0.7.0 在关闭/重载工坊时重置；0.8.0 改为仅取消未完成请求并保留本次成功会话，退出应用、清空对话或保存设置仍会重置。每次请求最多发送历史八条和当前消息一条；单条输入最多 2000 字，回复最多 8000 字，响应编码体积最多 256 KiB，超时 60 秒。失败与取消不写入上下文；迟到的旧请求不会覆盖已清空或新会话。密钥和请求仅由主进程使用，IPC 控制权限定为工坊主 frame，桌宠只读取回复显示状态。

0.6.0 首版采用非流式纯文本回复；0.7.0 本地检查点已增加流式输出，见 CHECKPOINT_07.md。程序不执行模型工具、不读取文件、不发送角色模型。模型输出按文本渲染，不插入 HTML。桌宠保持隐藏状态时也不会被回复自动弹出。清空会话清除应用内存中的上下文，不代表撤销已发往服务端的请求。

使用 OpenAI Responses API 的 `store: false` 与手动输入历史。该设置关闭 Response 存储，不能作为所有服务端日志保留策略的保证。接口依据：[Responses 迁移与状态说明](https://developers.openai.com/api/docs/guides/migrate-to-responses)。本功能不复用 ChatGPT 登录态或聊天记录，也不是 ChatGPT 官方宠物安装功能。

验证使用合成密钥与模拟网络：单元测试覆盖配置、失败回退、密钥不可读、上下文限制、取消竞态、超时、无效回复与大小边界；实际 EXE 验证真实系统加密保存、发送/气泡、纯文本显示、取消、清空、IPC 拒绝越权及重启配置恢复。没有提供真实 API 密钥，因此付费线上请求未验收。

后续：用户配置真实账户进行线上验证；流式输出已在本地实现，更多服务适配与语音后续单独规划。多屏/DPI/休眠硬件矩阵与 ChatGPT 官方宠物安装仍为未完成验收项。

## 0.6.1 本地检查点：失败恢复

发送失败或取消后，原消息会恢复到空白输入框；期间输入的新草稿不会被覆盖。“重试上一条”复用失败记录，并发送原消息，不替换后来写的草稿。成功后清除重试入口，清空对话同时清除失败记录。Ctrl/⌘+Enter 发送，Enter 换行；输入法组合键与按键长按不触发重复请求。配置初始化前禁用发送和设置修改，避免迟到的配置读取覆盖输入。

每个请求的可取消等待覆盖系统解密、网络连接和响应流；即使适配器不响应 AbortSignal，调用方也能结束等待。迟到响应的 body 会释放，不进入历史。移除密钥独立于未保存模型字段，安全存储不可用时也能移除已保存密文。设置写入后不再调用可能失败的原生可用性检查，关闭窗口导致的事件通知失败不会把成功保存报告成失败。

本检查点只本地提交并编译，不自动更新已发布的 0.6.0 附件。验证与限制见 CHECKPOINT_06_1.md。

## 0.8.0 本地检查点：会话恢复

工坊重开/刷新恢复最多四轮成功对话和最后一次失败或取消的消息，未完成片段仍明确标记且不进入上下文；未发送草稿不保留。桌宠在流式中途打开或刷新时读取当前回复状态。所有快照只读、按递增序列更新；完整会话只能由工坊读取，桌宠不能读取用户历史与重试原消息。详见 CHECKPOINT_08.md。

## 0.8.1 本地检查点：角色切换期间保留回复

混合回归复现了角色加载/名称同步覆盖桌宠气泡的问题：对话尚在主进程，但角色元数据显示结束时清空了气泡。现在将当前显示状态与画布分开保留，角色提交后重放文字和思考/回复动作，元数据同步不再清空回复。流式增量不反复重置动画时间；同一回复的重放不延长原有两秒挥手时限，过期后保留文字并恢复 idle。

新增 `npm run test:chat-mixed`：实际 EXE 中循环执行流式切换 VRM、隐藏接收回复、重新显示、切回精灵图、名称同步，以及既有取消重试/窗口重开/上下文滚动/迟到响应隔离检查；同时记录两个窗口的渲染资源计数。完整证据与限制见 CHECKPOINT_08_1.md，本轮仅保存本地提交，不自动发布。
