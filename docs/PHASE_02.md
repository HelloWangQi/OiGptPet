## 一、对三个问题的决定

### 1. 验证模型选哪一个？

**保留目前已成功加载并完成导出的 `VRM1_Constraint_Twist_Sample.vrm` 作为首个回归模型，第二个模型优先选 AvatarSample_A 的 VRM 1.0 导出版。**

第一阶段已有真实运行结果，没有必要重做首个验证模型。这里的官方示例、AvatarSample_A 和 Seed-san 是不同资源，记录时不得混称。

- AvatarSample_A 用于验证换角色后的骨骼、材质、表情及图集导出。必须核对具体文件版本；当前加载器仅支持 VRM 1.0，不能直接使用已有调研中标记为 VRM 0.0 的 Hub 文件。
- 优先确认是否能通过官方 VRoid Studio 样例获取并导出 VRM 1.0，保留来源、转换步骤、文件哈希和原始许可。官方许可允许将样例用于 VRM 应用及图像/视频作品，但这些样例不是 CC0；发布前仍需核对具体用法。[VRoid 官方样例条件](https://vroid.pixiv.help/hc/ja/articles/4402394424089-AvatarSample-A-Z)
- 如果获取或转换需要用户操作，先交付准确步骤并记录阻塞；不能用第一份模型改名、改元数据或重复导出后冒充第二份模型。
- Seed-san 保留为备用候选，文件版本与具体使用条件确认后再决定是否采用。本阶段不承诺实现通用 VRM 0.x 转换器。
- Alicia Solid 不纳入本阶段测试或默认演示，当前无需依赖其使用主体相关条件。

第二模型未实际取得时，通用导出功能可以先集成，但“两个真实模型验证”保持未完成。

### 2. 仓库/安装包是否默认只做本地导入，不附带源 VRM？

**是。仓库和默认发布包都不包含源 VRM 或用户模型。**

- 开发者显式执行 `npm run demo:fetch` 可下载示例用于本机验证；默认产品安装和启动不自动联网下载模型。
- 发布包中的模型界面应是友好的导入空状态，不给普通用户展示 npm 命令。
- 默认不附带由外部角色导出的精灵图；发布具体演示素材时，另行确认对应产物许可并记录来源。
- `.gitignore` 只控制 Git，不控制 Vite 的 public 复制或安装包内容。当前 `scripts/package.mjs` 复制整个 `dist`，可能把本机 `dist/models/demo.vrm` 带入包内，必须单独修正并做打包检查。
- 生产构建和发布包都要验证；开发示例必须通过明确的开发/测试选项进入验证构建，而非在普通发布构建里隐式附带。
- 角色模型和本地状态只存放在运行时的数据目录，不纳入打包输入。按实际分发文件保留必要的来源/许可说明。

### 3. inspectAtlas 与逐帧预览是否接入导出界面？

**是，这是本阶段主线。**

- 检查对象是实际编码完成的 PNG Blob：重新解码它，再把 RGBA、profile 和真实文件字节数交给 `inspectAtlas`。
- 本地检查报告应定位到行、帧，明确展示问题；结构失败时不能作为通过检查的宠物图集保存。
- 逐帧预览也必须读取同一份最终 Blob，不能用实时 VRM 或编码前画布替代导出结果。
- 显示九种动作的播放、暂停、逐帧检查，以及 v2 十六方向视线；v1 不显示视线功能。
- 分别显示“本地结构检查”“目标平台预检”“目标平台安装”三个状态。本地通过不得自动把另外两项标为通过。
- 正式发布前仍需目标平台真实预检与人工动作检查；安装完成需另有真实结果。本阶段不自动创建、选择或更换用户的 ChatGPT 宠物。

## 二、本阶段目标和顺序

交付一条可追溯的本地链路：**模型 → 透明 PNG → 精确文件检查 → 逐帧预览 → 保存 PNG 与诊断报告**。

预计双方各投入约 1–2 个工作日，再留半天联调；模型获取和人工平台操作可能另需时间。这是工作量估算。

1. DeepSeek 完成独立预览组件和第二模型准备说明；主开发者同时修正导出与打包流程。
2. 双方按本文接口对接，主开发者挂载组件到导出弹窗。
3. 使用最终 PNG 做回归；完成两个真实模型验证或如实记录缺项。
4. 保存测试证据、提交阶段检查点并暂停，等待用户同步。

## 四、给 DeepSeek 的直接开发任务

### D1：独立的浏览器图集预览组件，优先级最高

新增 `packages/atlas-preview/index.ts`，对外接口固定如下。类型可在该目录中拆分，但从 index 统一导出：

```ts
import type { AtlasInspection, AtlasProfile } from '../target-chatgpt/contract';

export interface AtlasPreviewResult {
  blob: Blob;                 // 调用者传入的同一个 Blob
  profile: AtlasProfile;
  inspection: AtlasInspection;
  sha256: string;              // 此 Blob 的 SHA-256，小写十六进制
  encodedBytes: number;        // 与 blob.size 相同
}

export interface AtlasPreviewController {
  load(blob: Blob, profile: AtlasProfile, signal?: AbortSignal): Promise<AtlasPreviewResult>;
  dispose(): void;
}

export function createAtlasPreview(host: HTMLElement): AtlasPreviewController;
```

行为要求：

1. 仅依赖浏览器 DOM/Canvas/Web Crypto 及现有 `atlas-tools`，不依赖 Electron/Node/Three.js，不新增运行时依赖。
2. `load` 解码最终 Blob，使用真实文件大小调用 `inspectAtlas`；返回结构报告与该 Blob 的哈希。支持格式限透明 PNG/WebP，限制文件体积和解码尺寸；不要因为类型名称就认为内容合法。
3. 文件损坏、无效 profile、错误 MIME/格式、尺寸或体积超限时给出明确失败。即使 MIME 缺失或声明被伪造，也不能绕过格式验证；可明确拒绝缺少 MIME 的输入，并在文档说明。
4. 可解码但结构失败的图片仍返回 inspection，让主界面显示具体错误；不要把它当作可播放的正常图集，也不因失败而留下上一份“通过”状态。
5. 可播放时使用已有 `getAnimationFrameRect`、`getLookFrameRect`。提供动作选择、播放/暂停、上一帧/下一帧、当前帧编号、v2 视线选择，显示原始 192×208 比例。
6. 跳跃动作保留原图中垂直位置；不重新裁切、居中、缩放单个角色，不重画或修补像素。导出缺陷必须被预览暴露出来。
7. v1 不渲染十六方向功能；动画不进入尾部透明格，切换动作不遗留上一动作的帧索引。
8. 本组件只操作自己的 host 子节点；CSS 用 `.atlas-preview-widget` 命名空间，不覆盖全局 button/body/canvas。
9. 组件负责销毁自己的 ImageBitmap、Object URL、事件和动画循环；`dispose` 可重复调用。重新加载、弹窗关闭、取消及过期异步结果都不能泄漏资源。
10. 同一实例并发 `load` 时以最后一次为准：过期或取消的调用拒绝为 `AbortError`，不能覆写新预览。`dispose` 后不允许旧异步任务恢复 UI。
11. `load` 完成后保留同一 Blob 的只读结果；主程序用返回的同一 Blob 保存。更换源文件后必须重新检查，不能沿用之前的通过状态。
12. 默认不自动播放；遵守 reduced-motion，用户可以手动开始。页面隐藏或组件销毁时停止动画调度。
13. 当前工坊已支持局域网 HTTP；该环境可能没有 `crypto.subtle`。SHA-256 需提供不依赖 Node 的纯浏览器回退，并用标准向量/已知文件验证；不能把哈希改成空值或伪值。无需新增运行时依赖。

不要在组件里保存文件、上传素材、修改主页面、添加全局快捷键或生成新的角色美术。

### D2：加固既有播放函数

检查并修复 `getAnimationFrameRect` 在极大但仍有限的 `timeSeconds` 与 fps 相乘溢出时可能返回 NaN 坐标的问题。保留正常输入的现有行为，为真实数值边界补回归测试；返回坐标必须始终指向合法帧。

如果发现其他边界问题，先修最小范围，保持当前公开签名和正常播放行为不变。不要把结构检测扩展成没有证据的视觉质量认证。

### D3：第二模型准备与记录

在 `docs/MODEL_VALIDATION_02.md` 记录当前官方回归模型和 AvatarSample_A 的获取/导出途径、具体 VRM 版本、模型名、作者、来源、哈希、原始许可和未确认项。明确区分“资料确认”“文件已取得”“程序已加载”“最终图集已导出并验证”。

仅有资料时不标记实际验证通过。可准备文件的只读信息和转换步骤；不要编辑主加载器以绕过 VRM 1.0 限制，也不要将模型二进制提交到 Git。若需要登录、购买或用户操作，记录具体步骤，继续完成不依赖该步骤的组件工作。

### D4：测试和交付

- 在现有 Vitest 内补纯逻辑回归测试；不得用只有类型检查的测试冒充 DOM 行为测试。
- 浏览器部分使用仓库已有 Playwright/Electron 依赖做独立 smoke 脚本，或交付完整可运行 fixture 和准确命令。fixture 必须能播放程序构造的测试图，测试图只用于验证控件，不用于创建宠物。
- 独立测试使用自己的临时目录和端口，关闭自己启动的进程，避免影响主工坊和主冒烟测试。
- 覆盖：有效 v1/v2、损坏 PNG、错误 profile/MIME、错误尺寸、超限文件、空帧/污染格、动作切换与循环、单步、方向边界、并发 load、取消、关闭及重新打开。
- 资源释放检查应验证调度和句柄确实被清理，不以某一时刻内存截图代替。
- 更新 `docs/ATLAS_PREVIEW.md`，给出挂载、load、dispose 的示例及错误/取消约定。
- 返回文件清单、接口变更（应为无）、实际运行命令、真实结果和未完成项；不提交或推送主开发者的改动。

## 五、主开发者 Codex 的任务

### C1：主界面接线

- 在导出弹窗创建专属 host，调用 `createAtlasPreview(host).load(finalBlob, profile)`，以返回的结果显示检查状态、行/帧错误、警告、字节数和哈希。
- 结构失败时禁用正常保存入口；更换模型、重新导出或取消时清除旧结果。关闭弹窗调用 dispose，重新打开重新建立组件，避免关闭期间继续播放。
- 成功检查后保存返回的同一 Blob；为它生成可单独保存的 JSON 报告，包含规格、SHA-256、检查结果、模型来源/许可引用和本地检查时间，不包含本地绝对路径等无关信息。
- 平台预检与安装初始状态明确为“未执行”；不得从 `inspection.valid` 推断平台通过。
- 在 DeepSeek 组件交付前，独立完善导出状态和保存生命周期，不自行再写一套预览模块。

### C2：落实默认不分发模型

- 生产构建显式排除开发用模型和下载元数据，开发/验证构建通过明确选项使用演示资源。
- 打包前后都检查没有源 `.vrm`、用户数据目录或本地导出素材；不要以 `.gitignore` 作为打包保障。
- 提供普通用户能理解的缺模型空状态，保留本地导入能力。
- 检查空包首次启动和已有本地模型启动两种路径。

### C3：统一联调与阶段交付

- 完成已有回归模型及第二模型的真实验证；若第二模型被获取条件阻塞，单独记录，不虚报通过。
- 检查九类动作、跳跃落地和十六方向，在最终图集的小尺寸预览上记录问题；只修会阻碍本阶段验收的渲染问题。
- 为损坏导出、结构失败禁用保存、重新导出和关闭重开补集成验证。
