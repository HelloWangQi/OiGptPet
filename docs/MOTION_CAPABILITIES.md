# 角色动作适配检查

0.8.4 起，VRM 成功加载后，工坊显示“动作适配检查”。展开后可查看手臂、腿部、躯干、头部、眨眼、开心/失落表情与视线控制器的加载情况。存在缺失项时自动展开提示；切换到精灵图后隐藏并清空结果，因为预渲染精灵图没有可检查的 VRM 骨骼。

检查来自当前实际加载的模型，不只读取文件的声明。它覆盖本项目程序动作使用的十个规范化骨骼与三个核心预设表情；0.8.6 另检查左右眼眨眼替代通道：

| 范围 | 检查项 | 缺失时的现有行为 |
| --- | --- | --- |
| 手臂 | leftUpperArm、rightUpperArm、leftLowerArm、rightLowerArm | 对不存在的骨骼跳过旋转，挥手和姿态可能不完整。 |
| 腿部 | leftUpperLeg、rightUpperLeg | 对不存在的骨骼跳过旋转，奔跑动作可能不完整。 |
| 躯干 | spine、chest、neck | 跳过对应旋转，思考、失落的姿态幅度可能减弱。 |
| 头部 | head | 跳过头部旋转，头部视线表现受限。 |
| 眨眼 | blink，或同时存在的 blinkLeft/blinkRight | 优先使用通用 blink；缺少通用表情时，两侧独立表情齐全才同步驱动。只提供一侧时不自动眨眼，避免意外单眼动作。 |
| 情绪 | happy、sad | 没有对应表情时保留骨骼动作，不合成替代表情。 |
| 视线 | 已加载的 lookAt 控制器 | 未加载时仍尝试使用头部转动表现视线。 |

此表描述应用的动作依赖，不是 VRM 规范的必需骨骼清单。缺少可选骨骼或表情不会仅因此阻止加载、播放或导出；格式、文件安全及加载器校验保持原有规则。视线控制器存在不证明眼睛骨骼、表情绑定、运动范围或视觉效果都正确；表情存在也不证明其绑定产生可见变化。

0.8.8 起，失落和认真工作会在原程序姿态基础上尝试调整手部落点。以已加载的 head/neck 距离作为比例，并跟随头部朝向：失落调整双手，工作只调整右手。每条链需要对应 UpperArm、LowerArm 和 Hand；头颈缺失、比例无效或某条链不完整时跳过相应适配，保留原角度。这里的十骨骼表没有新增 Hand 规范符合性判断；不能把表中无缺失解读为手指/手掌/衣物碰撞都已适配。使用说明见 [0.8.8 版本说明](releases/v0.8.8.md)。

## 导出报告

“保存检查报告”的 JSON 增加可选的 `modelCapabilities` 字段，包含：

- `schemaVersion: 1`、`source: "loaded-vrm"`。
- `bones.present/missing`、`expressions.present/missing`：限定在上述应用使用的能力清单内。
- `lookAtController`：控制器是否加载。
- 0.8.6 增加可选 `blinkMode`（combined/paired/none），表示实际选择的眨眼通道。`expressions.present/missing` 仍如实记录三个核心预设本身是否存在；paired 模式下 missing 仍可包含 blink，不伪造通用表情存在。旧报告没有此字段时，只能按原有通用 blink 信息解读。
- `visualReview: "not-reviewed"`：自动检查不代替人工视觉确认。

主报告版本仍为 1，新增字段为附加信息；没有运行时能力记录的旧调用者省略该字段，不伪造“全部支持”。导出开始时复制当前模型与能力记录，后续切换角色或更改数据不会改写已生成报告。模型重新加载时重新检查，不把旧报告当作新模型的结果。

PNG 的结构检查、动作能力记录、目标平台预检和安装状态各自记录：能力齐全不代表动作自然或 PNG 通过，更不代表已安装。请继续播放九种动作与十六个视线方向，检查裁切、遮挡、基线和动作语义；本版没有新增外部动作导入、自动重定向或视觉评分。

## 验证范围

单元测试覆盖缺少可选能力、头部/肢体缺失提示、模型间结果独立，以及异步导出前的能力快照。实际 EXE 检查使用本地演示模型和一份仅移除可选映射的临时副本，验证加载、界面提示、原生报告保存、坏文件导入保留、精灵图清理及切回原模型后的报告恢复。测试副本和报告只在忽略的本地产物目录，不随应用或公开仓库分发。

0.8.6 增加保留原模型左右眼绑定、仅移除通用 blink 的测试副本，实际加载并导出报告验证 paired 模式；没有眨眼通道的副本明确记录 none。实时显示和离线图集共用同一渲染路径。单测核对通用表情优先、双侧同步、下一帧张眼清零及单侧降级；这些检查不替代具体模型眼睑效果的人工视觉验收。

0.8.7 将四类六帧动作的眨眼峰值移到 2/3 周期，避免导出步长跳过原来的 3/4 峰值。四帧、五帧、八帧动作保留原时机；挥手的末帧闭眼后在下一循环首帧张眼。视线方向行仍使用 idle 的第 0 相位，不把闭眼烘焙进视线格。该修复作用于时间线，不改变模型能力判断。
