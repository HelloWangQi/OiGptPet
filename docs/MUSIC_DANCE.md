# 桌面音乐舞动

## 范围

首个版本只面向 Windows Electron 桌宠和已加载的 VRM 角色。用户主动点击“音乐舞动”后，应用通过 Electron 系统音频回环取得当前输出混音，在内存中分析低频能量与节拍并驱动程序化舞步。`getDisplayMedia` 要求同时申请屏幕视频和系统音频；Electron 提供可信窗口的屏幕源，渲染端拿到流后立即关闭视频轨，不显示、处理或保存画面。原始音频不写盘、不上传，也不用于识别歌曲或歌词。桌宠隐藏、音轨结束或用户停止时关闭采集。

精灵图必须具有对应舞蹈帧才可表现舞蹈；现有图集没有额外舞蹈状态，所以首版不为精灵图生成假舞步。ChatGPT 宠物运行在宿主环境，不能访问用户电脑的系统混音，本功能不延伸至宿主内。

## 开发阶段

1. **本机采集与分析**：通过 Electron [`setDisplayMediaRequestHandler`](https://www.electronjs.org/docs/latest/api/session) 只授权可见、可信桌宠顶层窗口发起的用户手势请求（工坊窗口无系统音频采集权限），使用 `desktopCapturer` 提供临时视频源并返回 Windows loopback 音频；`getDisplayMedia` 不允许 `video: false`，所以渲染端取得流后立即停止视频轨。随后使用 Web Audio `AnalyserNode` 计算低频能量、节拍脉冲和滚动 BPM；只取分析数值，不保留 PCM 或频谱缓存。Windows 的捕获路径基于 [WASAPI loopback](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)。
2. **VRM 程序化舞步**：按检测到的 BPM、强度和节拍脉冲调整身体摆动、手臂、腿部和弹跳；能量短暂下降时平滑减弱，静音后回到普通状态。音乐采集期间按当前性能档保持活动帧率。桌宠提供低/中/高灵敏度选择和当前 BPM 显示。手动挥手、对话动作与动作优先级后续在体验中调整。
3. **舞蹈动作源**：桌宠可在本地临时加载 `.vrma`、切换文件内片段，并按估算 BPM 选择接近整数音乐乐句的循环速度；无音乐时暂停外部舞步，回到普通姿态。该模式不把舞步保存进角色包。
4. **其他角色格式**：以后提供带舞蹈帧的精灵图模板；验证素材许可与 ChatGPT 图集格式后再考虑图集适配。

## 当前实现边界

- 目前已加入 Windows loopback 请求门控、用户点击开关、内存节拍分析、空闲状态下的 VRM 程序化舞姿、低/中/高节拍灵敏度与 BPM/播放速度/能量显示，以及可选 VRMA 舞步加载/片段选择/BPM 循环速度同步；节拍能量经过平滑，VRMA 尽量在下一次检测到的节拍开始（1 秒后仍未检测到则自动启动）；聊天和手动动作优先。停止或隐藏桌宠会使未完成的授权请求失效，并关闭已经取得的媒体轨和待恢复的音频上下文；迟到获准时会立即关掉媒体轨。系统音频流所需的视频轨取得后立即关闭，应用不呈现屏幕画面。
- `npm run build` 通过。测试、Windows EXE 打包、系统音频设备和实际歌曲体验尚未运行；节拍检测可能受低音量、强压缩或非稳定节拍音乐影响。
- 音乐开关默认关闭，每次需要用户主动开启；窗口隐藏时停止采集。VRMA 动作只保存在当前桌宠会话内存。
- 不提供全局音量录制、歌曲识别、歌词分析或音频上传。

## Windows 人工验收清单

- 用无声环境启动采集：BPM 应显示等待，角色保持普通待机；停止后控件隐藏。
- 分别播放鼓点明显、节奏较弱和低音量音乐：检查能量条、BPM 与舞姿响应，并试低/中/高灵敏度。
- 启动采集后暂停音乐，再恢复播放：确认静音时回到普通姿态，恢复后继续跟拍；检查长静音后 BPM 回到默认值附近。
- 在音频授权请求仍处于等待状态时隐藏桌宠或换成精灵图，然后等待请求返回：旧请求应被取消，不能在隐藏/不支持的角色上留下活动采集。
- 载入用户自己的兼容 VRMA，检查片段切换、静音暂停/恢复和 BPM 速度同步；换角色、清除舞步和关闭窗口后确认舞步/采集状态符合提示。
- 实际麦克风听写和 Windows 系统朗读单独验收，不能将它们当成音乐采集的输入或输出路径。

当前没有完成真实 Windows loopback、音乐素材、麦克风或系统朗读的人工验收。不同音频驱动、系统混音、低音量和非稳定节拍会影响检测结果；自动检测值仅作舞步控制，不是精确节拍器。
