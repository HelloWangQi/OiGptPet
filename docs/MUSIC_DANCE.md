# 桌面音乐舞动

## 范围

功能面向 Windows Electron 桌宠和已加载的角色。用户主动点击“音乐舞动”后，应用通过 Electron 系统音频回环取得当前输出混音，在内存中分析低频能量与节拍并驱动舞步：VRM 使用程序化动作或用户 VRMA，精灵图须另外导入真实舞蹈帧条带。`getDisplayMedia` 要求同时申请屏幕视频和系统音频；Electron 提供可信窗口的屏幕源，渲染端拿到流后立即关闭视频轨，不显示、处理或保存画面。原始音频不写盘、不上传，也不用于识别歌曲或歌词。桌宠隐藏、最小化、音轨结束或用户停止时关闭采集。

精灵图需要真实舞蹈帧才可表现舞蹈；桌宠可临时导入一张单独舞蹈条带 PNG，主图集与 ChatGPT 导出格式不变，详见[精灵图桌宠音乐舞步](SPRITE_DANCE.md)。ChatGPT 宠物运行在宿主环境，不能访问用户电脑的系统混音，本功能不延伸至宿主内。

## 开发阶段

1. **本机采集与分析**：通过 Electron [`setDisplayMediaRequestHandler`](https://www.electronjs.org/docs/latest/api/session) 只授权可见、可信桌宠顶层窗口发起的用户手势请求（工坊窗口无系统音频采集权限），并在异步取得屏幕源后复核窗口身份和可见状态；随后返回 Windows loopback 音频。`getDisplayMedia` 不允许 `video: false`，所以渲染端取得流后立即停止视频轨。随后使用 Web Audio `AnalyserNode` 计算低频能量、节拍脉冲和滚动 BPM；只取分析数值，不保留 PCM 或频谱缓存。Windows 的捕获路径基于 [WASAPI loopback](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)。
2. **VRM 程序化舞步**：按检测到的 BPM、强度和节拍脉冲调整身体摆动、手臂、腿部和弹跳；能量短暂下降时平滑减弱，静音后回到普通状态。音乐采集期间按当前性能档保持活动帧率。桌宠提供低/中/高灵敏度选择和当前 BPM 显示。手动挥手、对话动作与动作优先级后续在体验中调整。
3. **舞蹈动作源**：桌宠可在本地临时加载 `.vrma`、切换文件内片段，并按估算 BPM 选择接近整数音乐乐句的循环速度；无音乐时暂停外部舞步，回到普通姿态。该模式不把舞步保存进角色包。
4. **其他角色格式**：以后提供带舞蹈帧的精灵图模板；验证素材许可与 ChatGPT 图集格式后再考虑图集适配。

## 当前实现边界

- 目前已加入 Windows loopback 请求门控、用户点击开关、内存节拍分析、空闲状态下的 VRM 程序化舞姿、低/中/高节拍灵敏度与 BPM/播放速度/能量显示，以及可选 VRMA 舞步加载/片段选择/BPM 循环速度同步；节拍能量经过平滑，程序化摆动使用估算的拍内相位避免依赖应用启动时间，累积到两个有效间隔前显示“检测节拍中”，VRMA 尽量在下一次检测到的节拍开始（1 秒后仍未检测到则自动启动），稳定 BPM 估计前保持 1×、稳定后再按乐句调速；舞步会按估算 BPM 容忍稀疏鼓点，约 2.5 秒无能量后重置 BPM，长静音恢复会先回到 1×并从所选舞步开头重新起播；聊天和手动动作优先。精灵图可选导入独立的 192×208 帧 PNG 条带，按四拍节奏播放，采用当前帧 alpha 遮罩处理点击；该素材仅保留在桌宠会话内，主图集与 ChatGPT 导出不变。停止或隐藏桌宠会使未完成的授权请求失效；主进程也会在异步取源后复核窗口可见、非最小化且可信，并关闭已取得的媒体轨和待恢复的音频上下文。系统音频流所需的视频轨取得后立即关闭，应用不呈现屏幕画面。
- `npm run build` 通过。提交 `415b1e1` 的 `npm run verify:desktop` 通过，EXE 位于 `release/v0.11.0-1794298025444/OiGptPet-win32-x64/OiGptPet.exe`，发布包报告见 `artifacts/release-smoke/run-1794298042725/result.json`。真实 loopback 音乐、精灵图舞蹈条带、麦克风和系统朗读仍待人工体验；`npm test` 未运行。节拍检测可能受低音量、强压缩或非稳定节拍音乐影响。
- 音乐开关默认关闭，每次需要用户主动开启；窗口隐藏时停止采集。VRMA 动作只保存在当前桌宠会话内存。
- 不提供全局音量录制、歌曲识别、歌词分析或音频上传。

## 内置 VRM 舞步

- 原“基础律动”保持为默认风格，用户可切换到“怦然心动风格”或“猫步轻悄风格”；使用八拍关键姿态和拍内平滑过渡，整体动作由系统音乐节拍驱动。
- “怦然心动风格”采用明快的交替手势与侧步；“猫步轻悄风格”采用交叉步、重心与肩部反向摆动。两套是原创概括式编排，沿用用户提到的歌曲氛围方向，不逐帧复制 AOA 或特定演出的现成舞蹈。
- 内置编排只适用于 VRM 程序舞步；导入 VRMA 时以用户动作片段为准。精灵图仍需导入独立 PNG 动作帧条带。
- 真实角色之间的身高比例、骨骼朝向、袖摆和发丝动态不同，必须用目标角色检查手臂方向、腿部幅度和动作接缝；风格选择只在当前桌宠会话生效。

## Windows 人工验收清单

- 确认音乐控件只在 Electron 桌面宠物显示；VRM 使用 VRMA 舞步入口，精灵图在导入 PNG 舞蹈帧后才显示音乐入口；浏览器预览不显示采集控件。
- 用无声环境启动采集：BPM 应显示等待，角色保持普通待机；停止后控件隐藏。
- 分别播放鼓点明显、节奏较弱、低音量和慢速稀疏鼓点音乐：确认初期显示“检测节拍中”、稳定后才显示 BPM；检查能量条、舞姿响应和低/中/高灵敏度，稀疏鼓点间动作应平滑渐弱而非突然停住，真正暂停后也应及时回到待机。
- 启动采集后暂停音乐，再恢复播放：确认静音时回到普通姿态，恢复后继续跟拍；长静音后应再次显示“检测节拍中”，稳定后显示新的 BPM。
- 在音频授权请求仍处于等待状态时隐藏/最小化桌宠或切换成精灵图，然后等待请求返回：旧请求应被取消，不能在隐藏/不支持的角色上留下活动采集。
- 捕获期间断开或切换 Windows 输出设备：若媒体轨结束或音频上下文暂停/关闭，按钮应恢复为未运行状态，重新选择设备后可手动启动。
- 载入用户自己的兼容 VRMA，检查片段切换、稳定 BPM 前保持 1×、稳定后同步速度、长静音后回到 1×并从所选舞步开头重播，以及短暂静音暂停/恢复保留当前位置；换角色、清除舞步和关闭窗口后确认舞步/采集状态符合提示。
- 为精灵图导入[舞蹈帧 PNG](SPRITE_DANCE.md#舞蹈帧-png-格式)，检查节拍循环、清除/换角/退出释放以及当前帧透明区域仍可正确点击拖动；精灵图舞蹈不应进入 ChatGPT 导出。
- 实际麦克风听写和 Windows 系统朗读单独验收，不能将它们当成音乐采集的输入或输出路径。

当前没有完成真实 Windows loopback、音乐素材、麦克风或系统朗读的人工验收。不同音频驱动、系统混音、低音量和非稳定节拍会影响检测结果；自动检测值仅作舞步控制，不是精确节拍器。
