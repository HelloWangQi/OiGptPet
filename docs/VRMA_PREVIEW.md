# VRMA 本机预览与轨道匹配

0.9.2 起，工坊可从本机导入 VRM Animation（`.vrma`），并在当前加载的 VRM 上临时预览。0.9.3 起，导入和选择片段时会对照当前角色显示轨道名称匹配摘要。0.9.4 起，可选把当前片段写入导出图集的动作行。0.10.0 起，可将同一 VRMA 文件中的不同片段分别分配给多行动作；0.11.0 开始支持同时保留多个 VRMA 文件，并从不同文件选片段。文件按序号区分并显示各自占用大小；分配清单可直接预览每行当前使用的动作及其骨骼、表情和视线匹配摘要，面板也显示临时动作库总占用量。未加入清单的行继续使用内置动作。默认不替换任何行。

## 检查内容

- 骨骼：检查动作里有旋转轨道的标准人形骨骼，以及 hips 平移轨道，是否能在当前 VRM 找到对应规范化骨骼。
- 表情：检查预设和自定义表情轨道名是否存在于当前角色。
- 视线：如果动作包含视线轨道，检查当前角色是否加载了视线控制器。
- 无匹配的轨道可能不会播放；仍保留当前解析出的动画并允许预览，以便用户观察可用部分。

这是按目标名称进行的静态映射检查，不评估动作语义、骨骼绑定质量、角色比例、根位移、衣物/头发碰撞或视觉效果。名称匹配也不保证播放自然；应使用目标模型实际观看并确认。

选择并加入替换行后，导出器会从所分配 VRMA 片段的时长均匀采样对应行的帧；报告对单行替换继续使用 `externalAnimation` 字段，多行替换使用 `externalAnimations` 数组，均记录目标行、片段名、时长和源动作 SHA-256，不记录本机路径。每个动作文件上限 64 MiB，当前工坊的 VRMA 库总量上限 256 MiB；移除文件也会清掉引用该文件的行分配。替换行的语义由用户决定。例如把跳舞片段指定为“等待输入”会将它放在该动作行，程序不会自动改变含义或重定向动作。保存前应逐帧检查循环接缝、裁切、遮挡和动作语义。

## 隐私与保存范围

- 文件在本机渲染端解析，大小上限 64 MiB；动作中的外部资源请求会被阻止。
- 动作源文件只保留在当前工坊运行期间，不写入角色库或备份包。
- 用户选择替换动作行时，动作画面会编码进导出的 PNG；原 VRMA 源文件仍不会打包进 PNG 或报告。
- 该预览不会作用于精灵图桌宠。导出的 PNG 可按目标应用支持的方式用于精灵图宠物。
- 更换角色、清除动作或关闭工坊会释放当前 VRMA 预览。

自动化冒烟通过运行时生成的合成 `.vrma` 验证解析和画面播放；它不代表任意真实 VRMA 或任意 VRM 都兼容。0.10.0 已打包并发布，但该版本未运行测试套件、`npm run verify:desktop` 或打包后 EXE 冒烟。多行动作组合仍需实际导出图集检查及目标模型视觉验收；发布与构建状态见 [0.10.0 版本记录](releases/v0.10.0.md)。
