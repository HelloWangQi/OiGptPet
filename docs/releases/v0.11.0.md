# OiGptPet 0.11.0 开发检查点

> 开发中，基于本地分支 `codex/desktop-prototype`。本轮改动尚未编译、测试、打包或发布；不要用旧 EXE 验收。

## 本轮目标

- 工坊可在当前会话添加多份 VRMA 文件，选择活动文件预览其中片段。
- 每个图集动作行可引用一个文件和其中一个片段；同一行再次分配会更新来源和片段。
- 移除动作文件时，清掉它引用的行分配；未分配行保留内置动作。
- 当前动作库总缓冲上限 256 MiB，每个文件不超过 64 MiB；切换角色或清除动作会释放文件。
- 导出器按目标行装载/切换来源动作，报告为每行记录来源哈希，不记录文件路径。
- 文件选择器和分配列表显示文件序号与文件大小；分配项可直接预览对应文件与动作片段及轨道匹配摘要。
- 文件导入或来源切换期间临时禁用分配项操作，避免异步加载时预览/移除与来源切换交错。
- 工坊持续显示当前 VRMA 临时库占用和文件数，便于用户掌握 256 MiB 总量上限。
- 导出模块独立校验每个动作文件和去重后的动作源总量上限，避免绕过工坊界面调用时失去限制。

## 待检查

- 添加、切换、移除文件以及角色切换期间的异步竞争。
- 分配项直接预览时的来源切换、快速连续点击和移除分配竞争（已加操作锁，仍待自动化与实际 EXE 验证）。
- 同文件多片段、跨文件多行动作、单行动作兼容、未分配内置行和来源报告。
- 用户安排验证后运行相关自动化，再从最终源码运行 `npm run verify:desktop`；真实动作语义、循环、遮挡与裁切仍需人工验收。
