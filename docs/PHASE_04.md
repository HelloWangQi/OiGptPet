## 一个阶段的完成目标

用户可以把**当前已入库角色**备份成一个本地 `.oipet` 文件，在干净的浏览器或桌面应用中恢复原角色、名字和图集规格，并继续正常互动、切换和重启恢复。覆盖 VRM、v1/v2 PNG/WebP。备份包含原始角色文件的本地副本，不依赖用户原下载路径。

这是单个角色的备份，不包含账号、密码、应用设置或整个角色库；不做云同步、自动上传或批量覆盖旧库。ChatGPT 官方安装验收仍是双端首版的独立缺项，不因本阶段完成而标记成功。对话、语音和 Live2D 放到后续独立阶段。

选择这个范围的原因：0.3.0 已能保存和切换角色，但用户尚不能把已命名的角色直接带到新的应用数据目录或浏览器；角色库、原文件、图集规格也缺少一个可恢复的交付文件。本阶段给出直接可用的新能力，同时验证已有迁移和资源释放边界。

## 接口和数据约定

具体稳定签名见 [DeepSeek 阶段四任务](DEEPSEEK_PHASE_04.md)。`.oipet` 是单资源版本化容器，包含受限 UTF-8 清单及原始 Blob；清单携带名称、源类型、必要的图集规格、MIME、字节数和 SHA-256。格式不包含本机路径或账户信息。

- 保存精确原始资产，不重新编码 PNG/WebP 或转换 VRM；摘要来自实际字节。
- 容器校验与模型/图集校验分别执行；解码容器通过后仍必须走现有渲染器和角色库验证。
- 恢复沿用 0.3.0 的候选加载 → 库写入/激活 → 替换画面顺序；失败不替换当前可用角色。
- 同字节重复恢复复用已有身份，保留库内已有名字，不改变其他角色。仅恢复成功后切换当前选择。
- 备份保存前再次确认所选条目；保存/恢复期间切换、取消、关闭或过期异步结果不得保存成另一角色。
- 备份文件持有用户角色的原始副本，仅由用户保存到本地；界面用简短说明提示该内容，不引入额外许可审批流程。测试资产及备份文件不进入仓库或默认包。

## 验收门槛与明确边界

- [ ] VRM 与 v1/v2 PNG/WebP 的备份/解码实际字节和 SHA-256 一致，名字和规格保留。
- [ ] 从 profile A 保存文件，在干净 profile B 通过主界面恢复；桌面和浏览器各有证据。
- [ ] 重复导入不重复入库；现有别名不被覆盖；错误版本/坏清单/截断/摘要不符/超限/错误源规格不改变当前角色。
- [ ] 真正保存失败、取消、窗口关闭和迟到结果有清楚且一致的状态，无半条写入。
- [ ] 两种模式合计连续切换 20 次（一次选择另一个角色记一次），无崩溃/卡死/错误覆盖；记录每次类型与耗时、测试条件、资源探针和进程内存样本。短样本不称为长期无泄漏。
- [ ] 重启恢复、名字保存、精灵图命中与源 VRM 导出等既有行为仍正常；按改动运行必要回归，不无故重复全部重型矩阵。
- [ ] 生产构建、分发白名单和实际 Windows 包启动/恢复通过；默认仍无模型、备份或用户数据。
- [ ] 双方交付冻结，检查点区分已测/未测/平台未验收；完成后整理代码提交，推送状态据实核对，然后暂停。

完整一小时 soak、真实多屏/拔插/休眠、100%/150%/200% DPI、能耗和其他硬件仍作为专门稳定性验收；本阶段不为赶提交把这些项目勾为完成。ChatGPT 官方预检/安装单列后续实机验收，不能用备份格式或本地结构检查代替。
